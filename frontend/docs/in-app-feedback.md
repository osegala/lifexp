# Evrenthia in-app feedback review

Reviewed locally on October 21, 2026. This pass changes notification presentation and preserves existing gameplay triggers.

1. **Existing system found.** `CompletionFeedbackContext` already owns the task-reward FIFO, duplicate prevention, ad suppression, and building-upgrade queue. Task and building cards had separate visual implementations. Other existing feedback used two-argument native alerts or inline status/error text. Those queues and conditions remain in place. Destructive account deletion and notification permission confirmations retain their original native buttons and actions.

2. **Files changed.** The new reusable production files are `src/feedback/notices.ts`, `src/components/ui/GameNotice.tsx`, and `src/components/GameNoticeHost.tsx`. Existing alert call sites in Home, Tasks, Base, Avatar, Shop, and Profile now use the shared host. Existing task/building cards and inline save, reminder, store, ads, and recoverable-error states use the shared card. Root layout mounts one account-scoped host. Screen structure and ordinary loading placeholders retain their existing presentation. Test imports were updated to recognize the shared display contract; four focused tests exercise the actual notice store, host, and card. The [complete file manifest](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/changed-files.json) separates modifications from newly added files. Development review entry and screenshots are included below.

3. **Reusable component.** `GameNotice` supports title, optional message/icon, success/info/error/warning variants, optional dynamic XP/coin/World Point values, children for existing detailed feedback, dismissal, and announcements. `GameNoticeHost` owns automatic dismissal for the existing non-action alert sites: six seconds normally, eight for errors. Its session-local FIFO waits behind task/building celebrations and clears on account change. Existing inline states remain visible for their original state lifetime; they acquire no new timer. The implementation uses the existing painted HUD material, with no new dependencies or image assets.

4. **Visual variants.** Success uses forest green and a check icon; info uses a deep blue/forest tone and information icon; error uses muted red-brown and an alert icon; warning uses warm amber and a warning icon. All share an ivory foreground, restrained warm border, painted texture, rounded frame, and soft shadow. Base body-text contrast against the four solid surfaces ranges from 8.69:1 to 9.73:1. Icons and semantic labels distinguish states independently of color. [390px variants](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/variants-390.png) · [430px variants](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/variants-430.png).

5. **Task-completion presentation.** The compact card shows “Task Complete,” the actual task title and awarded XP/coins, any confirmed World Points, existing level/XP progress, confirmed totals, quests, and achievements. It reads the response values rather than the advisory task reward. The local screenshot response grants +35 XP and +4 coins; tests also verify different awarded values. The original 1.8-second reward animation and 2.8-second / 5.5-second completion lifetime remain unchanged. The card sits above the bottom navigation so task filters and completion controls stay available. [390px task completion](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/task-complete-390.png) · [430px task completion](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/task-complete-430.png).

6. **Animation and placement.** Floating cards enter with a 160ms fade and six-pixel slide, then fade over the final 180ms. Reduced motion removes this transition; preference resolution, event listeners, animations, and timers are cleaned up. Task notices dock above the navigation using its safe-area and font-scale allowance. Other ordinary notices sit below the top safe area and toolbar; Avatar feedback stays above the wardrobe. Building feedback sits below the resource HUD and above its detail controls. There is no blocking modal or particle animation.

7. **Accessibility.** Native feedback uses `AccessibilityInfo.announceForAccessibility`; the existing task/building announcement owners are preserved to avoid duplicate announcements. Web transient feedback has persistent polite status and assertive error live regions. Inline cards have the corresponding semantic live announcement. Dismiss controls have a 44×44 target and keyboard activation; Enter dismissal was exercised in the browser. The 320px review with text enlarged to 24px showed wrapping within all four card boundaries without horizontal overflow. [Enlarged text](/Users/owensegala/Productivity/productivity/frontend/docs/in-app-feedback/large-text-320.png). Native device and VoiceOver/TalkBack review were not run.

8. **Manual review and screenshots.** Real screen controllers ran in a separate DEV web entry with an isolated local Axios adapter and a simulated store provider. Unknown requests are blocked by that adapter. No real account, API write, ad, or store transaction was used. Task completion displayed the response rewards and automatically dismissed. Profile save showed success; its recoverable error retained entered values. Equipping Forestbound Dress changed the selected equipment and remained silent, preserving the pre-existing success behavior. A failed equipment change retained the previous item and displayed the existing inline plus transient error. Restore moved Free to confirmed Premium through the existing BillingClient verification path using local responses. Workshop upgraded from Tier 1 to 2 with the local resource balance changing from 412 to 312. Generic information feedback automatically dismissed. React Native Web emitted its existing pointer-event/shadow compatibility warnings; the web Animated driver also reported a JavaScript fallback during review. The shared card now explicitly uses the JavaScript driver on web and the native driver on iOS/Android. No application error was observed in these reviewed flows.
